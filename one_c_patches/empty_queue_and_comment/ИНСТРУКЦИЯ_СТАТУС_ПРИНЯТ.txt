ИНСТРУКЦИЯ: пустое состояние при создании + «Принят» в Clover после ручной смены в 1С
====================================================================================
Среда: только 1С TEST (копия). Production / VLAVKA — не трогать без отдельного «да».

Цель
----
1) При принятии заказа из Clover в 1С поле «Состояние заказа» остаётся пустым.
2) Когда менеджер вручную ставит в документе 1С любое состояние и записывает,
   у клиента в Clover статус заказа становится «Принят».

Часть A — модуль обмена (обязательно)
-------------------------------------
1. Откройте конфигуратор базы TEST.
2. Найдите общий модуль расширения Clover, куда раньше вставляли обмен
   (обычно Clover_ОбменКлиент / аналог с СоздатьТестовыйЗаказ).
3. Замените текст модуля на содержимое:
   Clover_module_для_вставки.txt
   (или примените Apply-Patch.ps1 / APPLY_PATCH.bat к выгрузке).
4. «Конфигурация» → «Обновить конфигурацию базы данных» → «Да» / «Принять».

В модуле уже есть:
- ОчиститьСостояниеЗаказа при создании;
- флаг CloverSkipAcceptedNotify на служебной записи создания;
- СообщитьОПринятииВClover → POST /api/one-c/orders/accepted;
- ОбработатьЗаписьЗаказаCloverПередЗаписью / …ПриЗаписи.

Часть B — две подписки на события (обязательно)
-----------------------------------------------
Без подписок смена статуса в форме 1С не вызовет callback в Clover.

1. В расширении: «Подписки на события» → добавить.

Подписка 1:
  Имя: Clover_ЗаказПокупателяПередЗаписью
  Источник: Документ.ЗаказПокупателя
  Событие: ПередЗаписью
  Обработчик: <ВашОбщийМодульClover>.ОбработатьЗаписьЗаказаCloverПередЗаписью

Подписка 2:
  Имя: Clover_ЗаказПокупателяПриЗаписи
  Источник: Документ.ЗаказПокупателя
  Событие: ПриЗаписи
  Обработчик: <ВашОбщийМодульClover>.ОбработатьЗаписьЗаказаCloverПриЗаписи

2. Снова обновить конфигурацию БД → «Да» / «Принять».

Часть C — проверка (TEST)
-------------------------
Предусловия: API Clover доступен с ПК 1С (сейчас в модуле 192.168.1.47:4100),
заголовки X-Clover-Key / X-Clover-Database: TEST настроены как для ACK.

1. В Clover поставьте тестовый заказ в очередь 1С TEST.
2. В 1С заберите заказ (как обычно).
3. Откройте созданный «Заказ покупателя»:
   ожидается пустое «Состояние заказа»; в Clover у клиента пока «Новый».
4. В 1С вручную выберите любое состояние → «Записать».
5. В Clover у клиента статус заказа: «Принят».
6. Повторная смена состояния в 1С не откатывает статус дальше «Принят».

Если запись в 1С проходит, а в Clover статус не «Принят»:
- журнал регистрации: событие Clover.AcceptedNotify;
- на API: POST /api/one-c/orders/accepted должен вернуть 200
  (при отсутствии ACK будет 409 ORDER_NOT_ACKED).

Откат
-----
