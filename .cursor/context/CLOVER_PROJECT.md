# Контекст проекта Clover

## Продукт

Clover — система принятия и обработки заказов для клиентов, менеджеров и администраторов с передачей заказов в 1С УНФ.

## Основные пользовательские роли

- Клиент: авторизация, персональная товарная матрица, корзина, адреса, заказ, история, связь с менеджером.
- Менеджер: клиенты, товарные матрицы, цены, заказы, статусы, сопоставление с 1С.
- Администратор: пользователи, права, настройки интеграций, среды, аудит.

## Критический контур

`Клиент создаёт заказ → Clover фиксирует неизменяемый ID → менеджер принимает → очередь 1С → 1С TEST получает заказ → создаёт новый документ → ACK содержит точный Clover ID и номер документа 1С → очередь завершается идемпотентно.`

Обязательные свойства:

- отсутствие дублей;
- точное соответствие заказа и документа 1С;
- повторный запрос не создаёт новый документ;
- ACK не может подтвердить чужой документ;
- TEST и production жёстко разделены;
- журналирование каждого этапа;
- безопасный откат;
- секреты не попадают в Git и отчёты.

## Технологический контекст

- React/Vite, PWA.
- Node.js backend.
- Windows 10 локально.
- GitHub.
- Интеграции: 1С УНФ, email, Telegram, MAX.
- Требуются отдельные TEST и production.

## Важное ограничение

Версия платформы и конфигурации 1С, активный компьютер, фактический путь проекта, IP и порты должны определяться диагностикой перед изменением. Исторические значения не использовать как доказанный факт.

## UX

Интерфейс должен быть адаптивным для браузера, Windows, Android и iOS/PWA. Критические операции должны иметь понятные статусы, подтверждения и восстановление после обновления страницы.

## Отложено до этапа маркетинга

Маркетинговые, SEO- и контент-агенты не включены в текущий набор. Их следует добавить после стабилизации приложения.
