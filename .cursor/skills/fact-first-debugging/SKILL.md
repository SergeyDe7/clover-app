# Когда использовать

Любая ошибка, 404/409/426/500, расхождение заказов, процессов, файлов или сред.

# Алгоритм

1. Зафиксировать точное ожидаемое и фактическое поведение.
2. Не менять систему до получения минимальных доказательств.
3. Определить активный процесс, путь, версию, среду и данные.
4. Построить максимум 3 различимые гипотезы.
5. Для каждой выбрать безопасную проверку без изменения данных.
6. Выполнить проверки и отбросить неподтверждённое.
7. Создать тест, воспроизводящий подтверждённую ошибку.
8. Внести минимальное исправление.
9. Повторить исходный сценарий и негативные сценарии.
10. Сформировать таблицу: факт → доказательство → результат.

Запрещено объяснять причину словами «могло быть», если проверка не выполнена.
