Критический приоритет — корректный заказ и отсутствие дублей.

Обязательно:

- изучить текущие маршруты, хранилище и журнал;
- использовать стабильный Clover order ID;
- GET/получение заказа не должно удалять его из очереди;
- ACK должен подтверждать только точный заказ и точный документ;
- повторный ACK должен быть идемпотентным;
- чужой номер документа должен блокироваться;
- TEST/production должны проверяться сервером, а не только UI;
- ошибки должны иметь машиночитаемый код и безопасное сообщение;
- секреты брать только из окружения;
- добавить unit/integration tests и проверить негативные сценарии.

Не ослабляй защиту ради прохождения теста. Любое временное послабление оформляй как явный feature flag только для TEST.
