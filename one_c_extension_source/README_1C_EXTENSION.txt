Это НЕ готовый файл .cfe.
Это проверенный по собранным метаданным исходный комплект, из которого мы
создадим расширение в вашем Конфигураторе. Готовый .cfe нельзя безопасно

Назначение версии 2.2
- GET /hs/clover/v1/health — проверка публикации.
- GET /hs/clover/v1/clients — первые контрагенты, только чтение.
- GET /hs/clover/v1/products — первая номенклатура, только чтение.
- POST /hs/clover/v1/orders/draft — намеренно заблокирован.

Почему запись заблокирована
Для корректного ЗаказаПокупателя нужно выбрать реальные значения:
- Организация;
- Договор;
- ВидЦен;
- ВалютаДокумента;
- СтруктурнаяЕдиницаПродажи;
- Ответственный.
Их безопасно получим после первого подключения и чтения справочников.

Создание расширения — выполнять вместе с инструкцией по шагам
1. Создать расширение CloverIntegration.
2. Создать HTTP-сервис с корневым URL clover.
3. Добавить шаблоны v1/health, v1/clients, v1/products, v1/orders/draft.
4. Связать методы GET/POST с функциями Health, Clients, Products,
   CreateDraftOrder из HTTPService_CloverExchange_Module.bsl.
5. Заменить CHANGE_ME_CLOVER_SECRET на длинный случайный ключ.
6. Сохранить расширение и проверить совместимость.
7. Опубликовать HTTP-сервис на IIS или Apache.

Не нажимайте «Обновить конфигурацию базы данных» для основной конфигурации.
Работа ведётся только через отдельное расширение.
