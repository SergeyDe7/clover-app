# Схема сервера (без домена)

```text
[ПК менеджера / клиента в LAN]
        |
        |  http://SERVER_IP:5273   (UI / PWA)
        |  http://SERVER_IP:4100   (API)
        v
[ VM / сервер Clover в датацентре ]
   frontend (Vite preview или static+proxy)
   backend Node.js :4100
   SQLite + uploads + .env
        ^
        |  http://SERVER_IP:4100/api/one-c/*
        |  X-Clover-Key + database=TEST
[ 1С УНФ TEST (копия) ]
```

## Ограничения текущего кода

- Pull-очередь и ACK разрешены **только** если 1С передаёт базу с именем `TEST`.
- Рабочая база VLAVKA / production **не** подключается этим же контуром без доработки и отдельного решения.
- Без домена и HTTPS: Passkey, части Web Push и cookie SameSite могут работать ограниченно — для LAN по IP обычно достаточно логина/пароля.

## Рекомендуемый порядок сред

1. Локальный моноблок (уже есть) — разработка.
2. Сервер датацентра + 1С TEST — приёмка.
3. Позже: домен + HTTPS.
4. Позже: отдельный prod-контур (после доработки кода и вашего «да»).
