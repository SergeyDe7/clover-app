## A. Домен и DNS (без публикации сервиса)

1. Зафиксировать домен (см. DOMAIN_RECOMMENDATION; кандидат prep: `clover-order.ru`).
2. Узнать у Андрея / ДЦ: публичный IP VM **или** IP reverse-proxy.
3. У регистратора: A-запись `@` → публичный IP; при необходимости `www`.
4. Дождаться распространения DNS (`nslookup` / `dig`).
5. **Не** открывать 5273/4100 в интернет напрямую — только через reverse-proxy с TLS.

---

## B. HTTPS (reverse-proxy)

1. На VM: Caddy **или** nginx (примеры в пакете `releases/dc-prep-*/caddy|nginx`).
2. Сертификат Let's Encrypt (или корпоративный TLS ДЦ).
3. Proxy:
   - UI → `127.0.0.1:5273`
   - API → `127.0.0.1:4100` (или единый origin с path `/api`)
4. Проверка снаружи: `https://<домен>/` → 200; health API по согласованному URL.
5. Закрыть прямой вход из интернета на 5273/4100 (firewall ДЦ).

---

## C. Переменные `.env` (после HTTPS)

В `server/.env` на VM (секреты не коммитить):

```env
APP_PUBLIC_URL=https://<домен>
CLOVER_PUBLIC_URL=https://<домен>
PASSKEY_RP_ID=<домен>
PASSKEY_ORIGIN=https://<домен>
```

Перезапуск systemd/процессов Clover.  
Smoke: логин по HTTPS, сессия держится, PWA-манифест отдаётся.

---

## D. Web Push (VAPID)

1. На сервере в каталоге `server`: `npx --yes web-push generate-vapid-keys`
2. Прописать `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` в `.env`
3. Перезапуск backend → `GET /api/push/status` → `"enabled": true`
4. На телефоне: установить PWA **по HTTPS** → «Включить уведомления»
5. Тест: событие менеджера → push + (по возможности) badge

Подробности: [PUSH_ENABLE.md](./PUSH_ENABLE.md).
