# Security Stage 7 — защита публичного каталога от массовой выгрузки

Дата локальной проверки: 2026-09-24.

## Подтверждённое исходное состояние

До изменения `GET /api/public/catalog` возвращал весь отфильтрованный каталог одним
ответом и не имел отдельного лимита чтения. Безопасный запрос к production вернул
HTTP 200, 691 товар и 503 261 байт JSON. Production этим пакетом не изменялся.

## Реализованные ограничения

- список каталога отдаётся страницами: по умолчанию и максимум по 60 товаров;
- ответ содержит `limit`, `offset`, `total`, `hasMore` и `nextOffset`;
- на список действует отдельный лимит 30 запросов в минуту на источник;
- каталог использует отдельное ограниченное хранилище лимитов и не может занять
  ёмкость защитных лимитов входа, регистрации или восстановления пароля;
- `X-Real-IP` считается доверенным только от loopback или точного proxy-IP из
  `CLOVER_TRUSTED_PROXY_IPS`; прямой клиент не может выбрать себе bucket;
- карточка товара по коду не ограничена этим лимитом, чтобы сохранить индексируемые
  товарные страницы;
- frontend, импорт фотографий и live-verifier читают все необходимые страницы явно;
- ответы `/uploads` получают `Cross-Origin-Resource-Policy: same-origin`;
- список каталога по-прежнему не раскрывает `details`, `priceSources`, режим наценки
  или процент наценки.

## Что это не гарантирует

Публичные цены, названия, изображения и товарные страницы неизбежно доступны
посетителю. Эти меры уменьшают скорость массовой выгрузки и стоимость простого
скрейпинга, но не являются DRM и не остановят распределённого бота с ротацией IP.
Лимитер хранится в памяти одного процесса: при нескольких экземплярах приложения
для общего лимита нужен внешний gateway/WAF или общее хранилище. CORP ограничивает
встраивание изображений чужими браузерными страницами, но не прямое скачивание.
Если nginx и Node работают на разных адресах, перед установкой в
`CLOVER_TRUSTED_PROXY_IPS` нужно указать точный адрес nginx. Подсеть и адрес Node
указывать нельзя. При локальном `proxy_pass` переменная остаётся пустой.

## Проверка и откат

Автоматический verifier `npm --prefix server run test:security-stage7-anti-scraping`
проверяет границы пагинации, доверие proxy-адресу, 31-й запрос с HTTP 429,
`Retry-After`, объединение страниц без дублей и CORP для uploads.

Откат пакета после будущего коммита — revert одного атомарного коммита и повторная
проверка каталога. До отдельной команды пользователя коммит, push, PR, merge и
deployment не выполняются.
