# Готовность проекта и путь к реальным заказам

Оценка на **29.07.2026** по проверенным фактам (не прогноз).

## Сводка готовности

| Контур | Оценка | Чем подтверждено |
|--------|--------|------------------|
| Локальное приложение (UI + API + SQLite) | **85%** | health 4.0.4, frontend 200, работа менеджера/клиента |
| Обмен Clover ↔ 1С **TEST** | **90%** | 2 успешных E2E (НФНФ-003276, НФНФ-003277) |
| Безопасность / разделение сред | **60%** | очередь только TEST в коде; prod-контур не проверен |
| Уведомления (SMTP / Telegram / Push) | **40%** | код есть; боевая настройка домена/HTTPS **не проверена** |
| Production / реальные заказы в рабочую 1С | **35%** | VLAVKA и prod **не трогали** |
| **Итого к «реальным заказам в прод»** | **~55%** | TEST готов; production checklist ниже не закрыт |

«100%» для интеграции 1С без проверки в целевой базе **не заявляется**.

## Что уже можно считать готовым (TEST)

1. Постановка заказа в очередь менеджером.
2. Получение заказа расширением 1С TEST.
3. Создание «Заказа покупателя» с привязкой `[CLOVER:uuid]`.
4. ACK с совпадением номера документа.
5. Повторный сценарий на новом заказе.

## Что делать дальше для реальных заказов

Порядок безопасный; каждый пункт — отдельное подтверждение.

### Этап A — закрепить TEST (до prod)

1. Закоммитить и (по вашему «да») сделать PR/merge ветки с агентами и документацией.
2. Зафиксировать в журнале: какой `.cfe` установлен в 1С TEST.
3. Чеклист негативных тестов: повторный get без нового заказа; чужой ACK; обрыв сети.
4. Согласовать правило единиц (упаковка в Clover ↔ штуки в 1С) — сейчас суммы сходятся, представление единиц может отличаться.

### Этап B — подготовка production (без реальных заказов)

1. Отдельная опубликованная база / контур **не TEST** с отдельным ключом `ONEC_API_KEY`.
2. Явное разделение URL и ключей TEST vs prod в `server/.env` (и процедура, кто имеет доступ).
3. `ONEC_ALLOW_LOCAL_WITHOUT_KEY=false` на сервере.
4. Backup рабочей базы 1С и Clover перед любым включением записи.
5. Настроить SMTP / публичный URL / HTTPS, если нужны письма и push.
6. Решение: prod-очередь по тому же pull-протоколу или отдельный режим (сейчас код очереди заточен под имя базы **TEST** — для prod нужна доработка и review).

### Этап C — пилот реальных заказов

1. Один пилотный клиент, один заказ, только после вашего явного «да».
2. Сверка: строки, цены, контрагент, адрес, номер документа, ACK в Clover.
3. План отката: не проводить документ / пометить ошибку / не повторять get.
4. Только после 3–5 чистых пилотов — расширение на поток.

**Сейчас не делать:** массовую выгрузку в VLAVKA, `ONEC_WRITE_ENABLED=true` без backup, push в GitHub без подтверждения.

## Риски

- Исторические пути/IP/порты в старых отчётах могут быть неактуальны — сверять диагностикой.
- В корне копились установщики и RESULT-логи — очищены в backup; актуальная правда в `docs/technical/` и коде.
