## Ваши дальнейшие действия (без домена → датацентр)

### Сейчас (локально)

1. Продолжать тестовые заказы только в **1С TEST / КОПИЯ**.
2. Не подключать VLAVKA.
3. Хранить журнал: номер Clover ↔ номер документа 1С.

### Подготовка сервера в датацентре

Следуйте [`docs/deploy/CHECKLIST.md`](../deploy/CHECKLIST.md):

1. Windows VM + Node ≥ 22.13 + внутренний IP.
2. `server/.env` из `docs/deploy/server.env.datacenter.example`.
3. Ключ `ONEC_API_KEY`, `ONEC_ALLOW_LOCAL_WITHOUT_KEY=false`.
4. Автозапуск: `tools\Install-CloverWindowsService.ps1`.
5. Firewall: порты 5273 и 4100 в LAN.
6. Приёмка: 2 тестовых заказа с сервера в 1С TEST.

**Установку на сервер агент не выполняет без вашего явного «да».**

### Когда появится домен

См. [`docs/deploy/AFTER_DOMAIN.md`](../deploy/AFTER_DOMAIN.md): HTTPS, Passkey, Push, SMTP, закрытие прямых портов с WAN.

### Реальные заказы (после сервера + TEST)

1. Отдельный prod-контур в коде (сейчас очередь только для имени базы `TEST`) — отдельная задача.
2. Backup 1С + Clover.
3. Пилот: 1 заказ → сверка → ваше «да» на расширение.

## Что уже можно считать готовым (TEST)

1. Постановка в очередь менеджером.
2. Получение заказа расширением 1С TEST.
3. Создание «Заказа покупателя» с `[CLOVER:uuid]`.
4. ACK с совпадением номера документа.
5. Повторный сценарий на новом заказе.

## Риски

- Исторические пути/IP в старых отчётах могут быть неактуальны.
- Без `dist` frontend не поднимется — `Start-Clover.ps1` теперь сам делает `npm run build` при отсутствии `dist`.
- Дублирующий `START_CLOVER.bat` сведён к вызову `START_CLOVER_V18.bat`.
