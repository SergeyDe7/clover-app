# Установка расширения Clover в рабочую 1С (VLAVKA)

Только после backup VLAVKA и явного «да».

Clover на DC уже принимает VLAVKA (`ONEC_PROD_EXCHANGE_ENABLED=true`, allowlist `TEST,VLAVKA`, default = **TEST**).

На сервере DC **нет** готового `.cfe` — расширение живёт в базе **TEST** на PC1 (моноблок). «То же расширение» = то, что сейчас работает в TEST, перенесённое в VLAVKA с одной правкой заголовка базы.

---

## Что именно переносится

| Объект в расширении | Зачем |
|---------------------|--------|
| Расширение **CloverExchange** | Оболочка |
| Общий модуль **Clover_ОбменКлиент** | Pull заказа, ACK, цены, меню |
| Команды / кнопки меню Clover | «Получить заказ», цены и т.д. |
| Подписки на `ЗаказПокупателя` (ПередЗаписью / ПриЗаписи) | Статус «Принят» в Clover после смены состояния в 1С |

Имя расширения и состав должны совпадать с TEST. Меняется только:

```bsl
X-Clover-Database → "VLAVKA"
```

Ключ (`ПолучитьКлючОбмена`) и адрес Clover (`192.168.155.15`, порт `4100`) — **как в текущем TEST**.

---

## Способ A (рекомендуемый): выгрузить `.cfe` из TEST → загрузить в VLAVKA

Делается **на PC1**, в конфигураторе.

### A1. Backup VLAVKA

Выгрузка ИБ / снимок — как вы делали ранее. Без свежего backup в VLAVKA не идём.

### A2. Выгрузить расширение из TEST

1. Запустите **1С:Предприятие** → выберите базу **TEST** (копия) → **Конфигуратор**.
2. Меню **Конфигурация** → **Открыть конфигурацию** (если дерева нет).
3. **Конфигурация** → **Расширения конфигурации**.
4. В списке найдите **CloverExchange** (имя может чуть отличаться — то, что уже работает с Clover).
5. Выделите расширение → сохраните в файл `.cfe`  
   (обычно кнопка/меню вроде **«Сохранить конфигурацию расширения в файл…»** / **Выгрузить в файл** — зависит от платформы; цель: один файл `CloverExchange_из_TEST.cfe` на диск).
6. Запомните путь, например:  
   `C:\Users\Lonovo\Desktop\CloverExchange_из_TEST.cfe`

Если в списке расширений пусто — в TEST расширение ставили иначе; переходите к **способу B**.

### A3. Загрузить расширение в VLAVKA

1. Закройте конфигуратор TEST.
2. Откройте **Конфигуратор** базы **VLAVKA** (рабочая).
3. **Конфигурация** → **Расширения конфигурации**.
4. Если **CloverExchange уже есть** в VLAVKA:
   - либо обновите из файла (замена),
   - либо удалите старое расширение Clover (только если уверены, что это старый/пустой черновик) и загрузите заново.
5. Если расширения ещё нет: **Добавить** / **Загрузить расширение из файла** → укажите `CloverExchange_из_TEST.cfe`.
6. Примите предупреждения совместимости, если платформа спросит (УНФ та же ветка, что у TEST — обычно ок).
7. **Конфигурация** → **Обновить конфигурацию базы данных** → **Да** / **Принять**.
8. Не закрывая VLAVKA, сразу сделайте правку заголовка (A4).

### A4. Обязательная правка: база = VLAVKA

1. В расширениях VLAVKA дважды щёлкните **CloverExchange**.
2. Слева: **Общие** → **Общие модули** → **Clover_ОбменКлиент** (двойной щелчок).
3. Найдите процедуру `ДобавитьЗаголовкиОбмена` (Ctrl+F: `X-Clover-Database`).
4. Было (из TEST):

```bsl
ЗапросHTTP.Заголовки.Вставить("X-Clover-Database", "TEST");
```

5. Должно стать:

```bsl
ЗапросHTTP.Заголовки.Вставить("X-Clover-Database", "VLAVKA");
```

Образец целиком: `one_c_patches/vlavka/ЗАГОЛОВКИ_VLAVKA.txt` (в репозитории на DC / на моноблоке в `clover-app`).

6. Проверьте рядом:
   - `ПолучитьКлючОбмена()` — тот же ключ, что в TEST и в `server/.env` → `ONEC_API_KEY` (ключ в чат не копировать).
   - HTTP-соединение на Clover: хост **`192.168.155.15`**, порт **`4100`** (как сейчас в рабочем TEST после переезда в ДЦ).
7. Ctrl+S → **Обновить конфигурацию базы данных** → **Да**.
8. Закройте конфигуратор. Откройте VLAVKA в режиме **1С:Предприятие**.

## Способ B: на диске уже есть готовый `.cfe`

На моноблоке ранее использовался пакет вида:

`CloverExchange_FINAL_WORKING_29_07_2026.cfe`  
(часто рядом с проектом: папка `Clover\` на Desktop, **не** обязательно внутри `clover-app`).

1. Найдите этот файл на PC1 (Поиск по диску: `*.cfe` / `CloverExchange`).
2. Загрузите его в VLAVKA как в **A3**.
3. Обязательно выполните **A4** (`VLAVKA` + ключ + IP DC).

Если файла нет — только способ A (выгрузка из живого TEST) или способ C.

---

## Способ C: VLAVKA уже содержит CloverExchange, но модуль старый

Как в TEST при патчах модуля (без нового `.cfe`):

1. Конфигуратор **VLAVKA** → расширение → модуль **Clover_ОбменКлиент**.
2. Ctrl+A → Delete.
3. Вставить актуальный текст из TEST:
   - либо скопировать модуль **целиком из конфигуратора TEST** (открыть TEST → тот же модуль → Ctrl+A → Ctrl+C → вставить в VLAVKA),
   - либо с моноблока файл  
     `clover-app\one_c_patches\price_types\ПОЛНЫЙ_МОДУЛЬ_вставить_целиком.txt`  
     (если это именно тот модуль, что сейчас в TEST).
4. Сразу заменить `X-Clover-Database` на **`VLAVKA`**.
5. Сохранить → обновить конфигурацию БД.
6. Проверить подписки (ниже).

---

## Подписки «Принят» (если после загрузки `.cfe` их нет)

В TEST они уже настроены. После загрузки `.cfe` обычно едут вместе с расширением. Если в VLAVKA подписок нет:

См. `one_c_patches/empty_queue_and_comment/ИНСТРУКЦИЯ_СТАТУС_ПРИНЯТ.txt` — две подписки на `Документ.ЗаказПокупателя` (ПередЗаписью / ПриЗаписи) на обработчики модуля Clover.

---

## Чего не делать из VLAVKA (пока)

- Не нажимать выгрузку **номенклатуры / контрагентов** в Clover — на сервере эти API пока только для **TEST**.
- Не менять в `.env` Clover: `ONEC_DEFAULT_EXCHANGE_DATABASE=VLAVKA`.
- Не ставить в заголовке снова `TEST` — иначе рабочая база будет забирать очередь копии.

---

## Проверка «расширение живое» (без пилотного заказа)

1. С PC1: браузер или из 1С — Clover UI `http://192.168.155.15:5273`, API health `http://192.168.155.15:4100/api/health`.
2. В 1С VLAVKA откройте меню Clover — пункты как в TEST видны.
3. В ЛК менеджера Clover → вкладка **1С**: бейдж `prod включён · базы TEST, VLAVKA`.

---

## Пилот одного заказа

1. Заказы → селект **Контур передачи** → **VLAVKA (рабочая)** → «Передать» → подтвердить.
2. В 1С VLAVKA: получить заказ из Clover (та же кнопка, что в TEST).
3. Документ создан → ACK уходит в Clover.
4. В Clover у заказа обмен `sent`/`draft`, номер документа 1С совпадает.
5. (опционально) смена состояния в 1С → у клиента статус «Принят».

Откат до ACK: в Clover «Отменить передачу». После ACK документ уже в VLAVKA — править/помечать в 1С по вашим правилам.
