# Установка и сопровождение расширения Clover в рабочей 1С (VLAVKA)

Только после backup VLAVKA и явного «да» — для **первичной** установки или аварийного переноса.
Если расширение **CloverExchange** в VLAVKA уже работает — **не переустанавливать**.

Обзор контура: [`PROD_CONTOUR.md`](./PROD_CONTOUR.md). Контракт API: [`INTEGRATION_1C.md`](./INTEGRATION_1C.md).

---

## Текущее рабочее состояние (после SEC-001)

На DC обмен владельца — **VLAVKA-only**:

| Параметр | Значение |
|----------|----------|
| `ONEC_PROD_EXCHANGE_ENABLED` | `true` |
| `ONEC_ALLOWED_DATABASES` | `VLAVKA` |
| `ONEC_DEFAULT_EXCHANGE_DATABASE` | `VLAVKA` |
| Inbound VLAVKA | `ONEC_VLAVKA_EXCHANGE_API_KEY` (отдельный contour credential) |
| Inbound TEST | **не используется** и **не обязателен**, пока TEST нет в allowlist |
| Local bypass | `ONEC_ALLOW_LOCAL_WITHOUT_KEY=false` |
| Legacy inbound | выключен (`ONEC_LEGACY_INBOUND_KEY_CONTOUR` не задавать при prod/VLAVKA) |

В расширении VLAVKA:

```bsl
X-Clover-Database → "VLAVKA"
ПолучитьКлючОбмена() → тот же секрет, что ONEC_VLAVKA_EXCHANGE_API_KEY на сервере
```

Адрес Clover: хост **`192.168.155.15`**, порт **`4100`**.

**SEC-001:** у каждого разрешённого контура — свой inbound key. Shared key между контурами запрещён. `ONEC_API_KEY` — outbound Clover → 1С, не multi-contour inbound. Реальные ключи, fingerprint и секреты в документацию и чат не копировать; хранение только в защищённом `server/.env` (и runtime процесса).

## Сопровождение уже установленного расширения

Рабочее расширение в VLAVKA **не переустанавливать** и не заменять из TEST без аварии.

### Ротация inbound-ключа VLAVKA

1. Backup VLAVKA + Clover (включая `server/.env`).
2. На DC: записать новый `ONEC_VLAVKA_EXCHANGE_API_KEY` в `server/.env` (helper/runbook владельца), restart API по штатному runbook.
3. В конфигураторе VLAVKA: расширение **CloverExchange** → модуль **Clover_ОбменКлиент** → изменить **только** `ПолучитьКлючОбмена()` на тот же новый секрет.
4. `X-Clover-Database` оставить `"VLAVKA"`. Остальной модуль не трогать без отдельной задачи.
5. Проверка без пилотного заказа: кнопка «Получить заказ» при пустой очереди → «Нет новых заказов».

### Что не делать

- Не ставить shared key (один секрет на TEST и VLAVKA).
- Не возвращать в заголовке `TEST` из рабочей базы.
- Не включать TEST в allowlist «на всякий случай» без отдельного `ONEC_TEST_EXCHANGE_API_KEY`.
- Не выгружать каталог из TEST поверх VLAVKA без необходимости — последняя выгрузка перезаписывает поиск в Clover.

## Каталог и контрагенты из VLAVKA

Clover принимает выгрузки из баз **текущего allowlist** (сейчас только VLAVKA):

- «Отправить товары/цены» → `POST /api/one-c/products-preview`
- «Отправить контрагентов» → `POST /api/one-c/clients-preview`
- цены (sale / purchase) — с `X-Clover-Database: VLAVKA`

Выгрузка наполняет поиск/сопоставление (`oneCProducts` / `oneCClients`), а **не** матрицу клиента и не «весь сайт» сама по себе. Дальше в ЛК: связать товары → матрица клиента.

Проверка: ЛК менеджера → Товары / «Каталог 1С» → свежая выгрузка с `sourceDatabase: VLAVKA`.

## Проверка «расширение живое» (без пилотного заказа)

1. Clover UI `http://192.168.155.15:5273`, API health `http://192.168.155.15:4100/api/health`.
2. В 1С VLAVKA меню Clover видно; «Получить заказ» при пустой очереди → «Нет новых заказов».
3. В ЛК → вкладка **1С**: статус отражает allowlist (VLAVKA-only: база VLAVKA, prod включён).

## Пилот одного заказа

Только по явному решению владельца (не часть обычной ротации ключа).

1. Заказы → **Контур передачи** → **VLAVKA** → «Передать».
2. В 1С VLAVKA: получить заказ из Clover.
3. Документ создан → ACK в Clover; обмен `sent`/`draft`, номер документа совпадает.
4. Откат до ACK: в Clover «Отменить передачу». После ACK — правки в 1С по вашим правилам.

## Исторический / аварийный путь: первичная установка или перенос `.cfe`

Ниже — **не** основной рабочий путь. Использовать только если расширения в VLAVKA ещё нет или оно безвозвратно сломано. Предпочтительно восстановить из backup VLAVKA, а не копировать из TEST.

На сервере DC **нет** готового `.cfe`. Источник при аварии — backup VLAVKA или (хуже) выгрузка из TEST на PC1 с обязательной правкой заголовка и **отдельного** VLAVKA key.

### Что входит в расширение

| Объект | Зачем |
|--------|--------|
| Расширение **CloverExchange** | Оболочка |
| Общий модуль **Clover_ОбменКлиент** | Pull, ACK, цены, меню |
| Команды / кнопки меню Clover | «Получить заказ», цены и т.д. |
| Подписки на `ЗаказПокупателя` | Статус «Принят» после смены состояния в 1С |

Обязательные отличия в VLAVKA: `X-Clover-Database = "VLAVKA"` и отдельный `ПолучитьКлючОбмена()` ↔ `ONEC_VLAVKA_EXCHANGE_API_KEY`.

### Способ A (аварийный): `.cfe` из TEST → VLAVKA

Делается **на PC1**, в конфигураторе. Свежий backup VLAVKA обязателен.

1. **Конфигуратор TEST** → **Расширения конфигурации** → **CloverExchange** → сохранить в `.cfe`.
2. **Конфигуратор VLAVKA** → загрузить/обновить расширение из файла → **Обновить конфигурацию базы данных**.
3. Сразу правка модуля **Clover_ОбменКлиент**:
   - `X-Clover-Database` → `"VLAVKA"` (не оставлять `TEST`);
   - `ПолучитьКлючОбмена()` → отдельный VLAVKA credential (не shared / не TEST key);
   - хост `192.168.155.15`, порт `4100`.
4. Образец заголовков: `one_c_patches/vlavka/ЗАГОЛОВКИ_VLAVKA.txt`.
5. Сохранить → обновить конфигурацию БД → проверить в режиме 1С:Предприятие.

Если в TEST расширений нет — способ B или C.

### Способ B (аварийный): готовый `.cfe` на диске

Иногда на моноблоке лежит пакет вида `CloverExchange_FINAL_WORKING_*.cfe` (часто рядом с `Clover\` на Desktop, не обязательно в `clover-app`).

Загрузить в VLAVKA как в A, затем **обязательно** те же правки заголовка, ключа и IP, что в A3.

### Способ C (аварийный): модуль в VLAVKA есть, но устарел

Без нового `.cfe`: в конфигураторе VLAVKA заменить текст **Clover_ОбменКлиент** актуальной копией (из backup / с моноблока `one_c_patches/...`), сразу выставить `X-Clover-Database = "VLAVKA"` и VLAVKA key → сохранить → обновить БД → проверить подписки.

### Подписки «Принят»

После загрузки `.cfe` обычно едут с расширением. Если нет — см. `one_c_patches/empty_queue_and_comment/ИНСТРУКЦИЯ_СТАТУС_ПРИНЯТ.txt`.
