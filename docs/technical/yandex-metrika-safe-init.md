# Яндекс Метрика — безопасное подключение (подготовка)

Счётчик: `112814607`. Документ не заявляет юридическую готовность и не разрешает production ON.

## Build-time флаг

`VITE_YANDEX_METRIKA_ENABLED` вшивается в JS на `vite build`.

- Значение в `server/.env` или в shell **после** сборки не переписывает уже отданный бандл.
- Чтобы выключить на сервере: собрать UI **без** `=1`, выложить новые hashed assets, затем пользователи должны перезагрузить вкладку.
- Уже открытые вкладки со старым бандлом продолжают старый код до reload.
- Отзыв согласия в новой версии останавливает дальнейший сбор **в этой вкладке** сразу (`destruct` + `disableYaCounter` + снятие `tag.js`).
- `VITE_YANDEX_METRIKA_TEST_MODE=1` только для isolated off-live проверок. В этом режиме localhost разрешён, а `mc.yandex.ru` не подключается.

## Рабочий порядок отключения

1. Не ставить `VITE_YANDEX_METRIKA_ENABLED=1` в production-сборке (текущий `.env.production` так и живёт).
2. Если флаг уже был влит в live JS: новая сборка без флага + выкладка assets + reload вкладок.
3. Пользователь может отозвать согласие в футере «Настройки аналитики» — это останавливает дальнейший сбор, но не удаляет уже отправленное.
4. Откат ветки / не деплоить её.

## Заказы и реклама

- `order_submitted` только после успеха публичного `POST /api/public/orders`.
- Заказы ЛК (`PUT /api/state/orders`) **вне аналитики**. Рекламная отчётность по кабинету и по «оплаченный новый клиент» из Метрики **не считается**.
- `order_submitted` ≠ оплата и ≠ новый покупатель. Стоимость оплаченного нового клиента — только сверка с фактическими продажами.
- В URL hit сохраняются только безопасные по **ключу и значению** параметры: `utm_*` (токены `[A-Za-z0-9._~-]{1,80}`), `yclid` / `ymclid` / `ysclid` / `gclid` (1–128 `[A-Za-z0-9]`).
- `utm_*` с пробелами, кириллицей, email или телефоном (включая `921…` / `7921…` без `+`) отбрасывается — имя параметра само по себе не доказывает отсутствие ПДн.
- Длинные числовые `yclid` сохраняются: правило click id не ищет телефонную подстроку внутри `[A-Za-z0-9]{1,128}`. Этот формат не доказывает отсутствие любых персональных данных.

## Согласие

Отдельный opt-in, не связан с обязательным согласием при заказе и со страницей `/personal-data-consent`.
Запись: `localStorage.clover-analytics-consent-v1` = `{"version":1,"status":"granted"|"denied"}`.
Нет записи / другая version = нет решения ≠ согласие.

## Политика — предлагаемые правки (не внесены)

Текущая `/privacy-policy` говорит, что использование сайта означает согласие с политикой, и не называет Яндекс Метрику. Для opt-in аналитики этого недостаточно. Предлагаемый отдельный абзац (черновик, без юр. готовности):

> На витрине может использоваться сервис «Яндекс Метрика» (ООО «ЯНДЕКС») для учёта посещений и действий. Счётчик загружается только после отдельного добровольного согласия в баннере «Необязательная аналитика». Каталог, вход и заказ работают без этого согласия. Отказ или отсутствие ответа не считаются согласием. Согласие можно изменить или отозвать в подвале сайта («Настройки аналитики»). Отзыв останавливает дальнейший сбор на этом устройстве и не удаляет данные, которые уже могли быть переданы. Это согласие не заменяет согласие на обработку персональных данных при оформлении заказа.

Также предлагается сузить фразу «Использование сайта означает согласие…», чтобы она не читалась как согласие на необязательную аналитику.
