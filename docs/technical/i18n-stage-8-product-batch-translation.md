# Stage 8 — пакетный перевод товаров (провайдер отключён)

**Scope:** подготовка пакетного перевода публичных полей каталога через admin-кнопку «Перевести новые товары». Автоперевод по умолчанию **отключён**. Подключение облачного переводчика отложено.

Это **не** отдельная система публикации: результаты пишутся в существующий Stage 4 контракт `product_translations` как `AUTO_MACHINE_DRAFT` (отображение и приоритет MANUAL — как в Stage 4).

## Состояние по умолчанию

- `CLOVER_PRODUCT_TRANSLATION_PROVIDER=disabled` (или переменная не задана).
- Кнопка видна администратору; запуск блокируется текстом «Автоперевод пока не подключён» + пояснением про русский fallback.
- Preview числа ожидающих полей — read-only, без сети, без резерва лимита, без заданий и без AUTO-записей.
- Заказы, комментарии заказов и обмен 1С не изменяются: комментарии по-прежнему уходят на исходном языке.

## Провайдеры

Серверный явный реестр (без произвольных URL и динамической загрузки):

| id | Статус |
|----|--------|
| `disabled` | default |
| `azure` | adapter реализован; **реальный API не проверен** |

Неизвестный id (например `yandex`) безопасно запрещает запуск (`UNKNOWN_PROVIDER`).

Тестовый adapter (`productTranslationProviderTest.js`) **не** входит в runtime-реестр и недоступен через env. Он инжектируется только в verifier.

### Как добавить другой провайдер позже

1. Реализовать adapter с контрактом из `server/src/productTranslationProvider.js` (доступность, языки, лимиты запроса, `estimateUsage`, `translateBatch`, confirmed/uncertain usage на ошибках).
2. Зарегистрировать id **только** в `resolveRuntimeProductTranslationProvider` (явный switch/map).
3. Добавить собственные env (секреты только server-side) и **отдельный** bucket учёта по `provider_id` (таблица `product_translation_provider_usage`).
4. Покрыть mock-тестами; UI и сохранение AUTO/MANUAL не переписывать.

Лимит `1 800 000` и `CLOVER_PRODUCT_TRANSLATION_MONTHLY_LIMIT` относятся к **конфигурации Azure**, не к универсальной бесплатной квоте других сервисов.

### Как подключить и проверить в TEST (отдельно)

1. Выдать разрешение на секреты только в TEST.
2. Задать `CLOVER_PRODUCT_TRANSLATION_PROVIDER=azure` и `CLOVER_AZURE_TRANSLATOR_KEY` / `CLOVER_AZURE_TRANSLATOR_REGION` в TEST secrets (не в Git).
3. Проверить preview → confirm на малом пакете; убедиться, что MANUAL не перезаписываются.
4. Production — только после отдельного разрешения на deploy.

### Как выключить перевод

`CLOVER_PRODUCT_TRANSLATION_PROVIDER=disabled` или удалить ключ Azure. Каталог, MANUAL и актуальные AUTO не затрагиваются.

## Отложенные проверки

- Реальный вызов Azure / другого API и качество перевода.
- Установка на TEST/production и работа с живыми секретами.
- Публичное включение иностранных языков (отдельный этап).
- Перевод комментариев заказов в 1С (отложено).
