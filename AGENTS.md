# Clover — правила работы AI-команды

## Единая точка входа

Пользователь общается только с оркестратором `@dsd`.
`@dsd` сам выбирает специалистов, распределяет работу, принимает результаты и отвечает пользователю единым итогом.

Писать `@dsd` в каждом сообщении **не обязательно**: агент и так работает как оркестратор (правило `.cursor/rules/001-dsd-default.mdc`). Ответы пользователю начинаются с `@dsd`.

## Цель проекта

Clover принимает клиентские заказы, позволяет менеджерам и администраторам их обрабатывать и корректно передаёт заказы в 1С УНФ. Приложение должно работать в браузере, как PWA на Android/iOS и на Windows.

Роли пользователей: клиент, менеджер, администратор.

## Текущий стек

- Frontend: React/Vite/PWA.
- Backend: Node.js.
- Интеграция: 1С УНФ, почта, Telegram, MAX.
- Среды: TEST и production должны быть разделены.
- ОС разработки и локального запуска: Windows 10.
- Репозиторий: GitHub.

## Обязательный процесс

1. Зафиксировать задачу, критерии готовности и факты текущего состояния.
2. Составить план и определить риски.
3. Сделать резервную копию затрагиваемых данных/файлов.
4. Создать отдельную Git-ветку, если репозиторий доступен.
5. Реализовать изменение.
6. Запустить автоматические проверки и фактические тесты.
7. Провести независимый review.
8. Подготовить отчёт, откат и безопасную установку.
9. Запросить подтверждение пользователя перед рискованным действием.

## Действия только после подтверждения пользователя

- изменение или миграция базы данных;
- обновление расширения/конфигурации 1С;
- удаление или необратимое изменение файлов;
- `git push` (команда «коммит» = коммит + обычный push ветки + промпт для нового чата), создание/слияние Pull Request;
- публикация или установка на сервер;
- переключение TEST/production;
- отправка реальных писем/сообщений;
- действия с реальными заказами и рабочей 1С.

## Факты вместо предположений

- Не писать «вероятно», «должно работать», «могло произойти» как итог проверки.
- Гипотеза всегда помечается как гипотеза.
- Причина считается подтверждённой только после воспроизводимого теста, лога, diff, ответа API, записи БД или визуальной проверки.
- Если факт не проверен, прямо написать: «не проверено».
- Не заявлять полную готовность интеграции 1С без реального теста в 1С TEST.

## Коммуникация с пользователем

- Писать по-русски.
- Давать пользователю по 3–5 действий за сообщение.
- Для продолжительных задач показывать реальные этапы по 10%: что завершено, чем подтверждено, что выполняется дальше.
- Не просить пользователя вручную редактировать код, если агент может сделать это сам.
- Не обещать фоновую работу. Отчёт о прогрессе должен соответствовать фактически выполненной работе.

## Качество

Приоритеты продукта (при конфликте `@dsd` показывает компромисс и выбирает безопасный вариант):

1. Скорость полезных фич.
2. Стабильность обмена с 1С УНФ.
3. Красивый и понятный UI.
4. Маркетинг и рост.
5. Безопасность и разделение сред.

Не жертвовать идемпотентностью заказов и разделением TEST/production ради скорости.

## Перед началом каждой задачи

`@dsd` обязан прочитать:

- этот файл;
- `.cursor/context/CLOVER_PROJECT.md`;
- `git status` и последние коммиты;
- актуальные `package.json`, scripts и конфигурацию окружения;
- затрагиваемые тесты и документацию.

Исторические пути, IP, порты и версии нельзя считать актуальными без повторной проверки.
