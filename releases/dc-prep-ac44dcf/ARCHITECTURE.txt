Архитектура заказчика (зафиксировано 2026-08-02)
================================================

Цель этапа 1
------------
В ДЦ — только Clover (Linux VM).
1С и рабочие места 1С — НЕ переносить и НЕ перенастраивать.

Схема
-----
  [ДЦ]  Linux VM: Clover UI :5273 + API :4100
           ↑
           |  канал офис ↔ ДЦ (обычно VPN / L2/L3 от площадки)
           ↓
  [Офис] Комп1: база 1С как сейчас, 24/7 включён
         Рабочие места 1С на компе1 — без изменений

  Моноблок: разработка Clover (Cursor). Не обязателен как клиент 1С.

Зависимость от компа1
---------------------
• Clover (сайт, заказы в sqlite) работает, даже если комп1 выключен.
• Обмен с 1С (очередь, ACK, документ в 1С) — только пока комп1 онлайн
  и есть сеть до Clover в ДЦ.
• Заказчик: комп1 держать 24/7.

VPN — для чего
--------------
VPN (или аналог от ДЦ) нужен, чтобы 1С на компе1 видела Clover в ДЦ:
  http://<IP_Clover_в_ДЦ>:4100
Это НЕ про Cursor и НЕ про перенастройку мест 1С.
RDP для Linux-VM Clover не нужен (достаточно SSH / SFTP).

Бэкапы
------
• Clover VM: снимки гипервизора (перед снимком — stop clover-*).
• 1С: живая база остаётся на компе1; бэкап 1С делается на компе1,
  копии можно складывать в хранилище ДЦ (отдельная задача, не установка Clover).

Обмен 1С ↔ Clover (этап 1)
--------------------------
• Пока только база имени TEST (не VLAVKA / не prod без отдельного «да»).
• В 1С на компе1: URL API сменить на Clover в ДЦ + X-Clover-Key.
• Рабочие места 1С не трогать.

Этап 2 (позже, отдельное «да»)
------------------------------
Домен clover-order.ru + HTTPS + VAPID / push.
DNS сейчас: A → 81.177.141.15 (сверить: наша VM или парковка).

Что Андрею делать по 1С
-----------------------
Не переносить базу. Обеспечить сеть комп1 → Clover:4100.
Ключ ONEC_API_KEY согласовать с тем, кто правит расширение на компе1.
【АНДРЕЙ】 уточнить: кто меняет URL в расширении 1С на компе1.
