КАК РАБОТАЕМ ПОСЛЕ ПЕРЕЕЗДА CLOVER В ДЦ
Понятная инструкция для заказчика
Дата: 2026-08-02
================================================================================

Коротко
-------
Правки делаем КАК СЕЙЧАС — на моноблоке в Cursor.
На сервер в ДЦ изменения попадают ОТДЕЛЬНЫМ шагом (выкат), не «сами собой».
1С на компе1 не трогаем при каждой правке Clover.


1. Что где живёт
----------------

  МОНОБЛОК (как сейчас)
    • Cursor + @dsd
    • пишете задачу → я меняю код → проверяем локально
    • «коммит» → код уходит в GitHub

  ДЦ (Linux VM)
    • работает Clover для людей (сайт / приложение)
    • код обновляется только когда ВЫКАЧИВАЕМ новую версию с GitHub

  КОМП1 (офис, 24/7)
    • база 1С как сейчас
    • рабочие места 1С не перенастраиваем из‑за правок Clover
    • обмен с Clover в ДЦ идёт по сети (часто через VPN)


2. Обычный цикл доработки (почти как сейчас)
--------------------------------------------

  Шаг 1. Вы пишете в чат Cursor, что нужно изменить.
  Шаг 2. @dsd правит код на МОНОБЛОКЕ и проверяет локально.
  Шаг 3. Вы пишете «коммит» (если нужно отправить в GitHub / PR).
  Шаг 4. После merge в main — ВЫКАТ на ДЦ (см. раздел 3).
  Шаг 5. Проверяете на сервере: логин, заказ, при необходимости обмен с 1С.

Для вас это почти тот же режим: «написал → посмотрел результат».
Разница одна: на сайте в ДЦ новое появится после выката, не в ту же секунду.


3. Как обновляем сервер в ДЦ
----------------------------
Подробно «как выглядит» — файл DEPLOY_TO_DC.txt в этой же папке.

Кратко:
  • Сначала правка на моноблоке и «коммит» в GitHub.
  • Потом выкат: git pull → npm ci → build → restart служб → проверка сайта.
  • Делает Андрей по вашей просьбе ИЛИ вы по SSH (шпаргалка в DEPLOY_TO_DC.txt).
  • Обычный выкат не трогает базу заказов и .env.
  • Перед крупным обновлением — снимок VM.


4. Чего НЕ делаем
-----------------

  • Не правим код «на живую» только на сервере и забываем про Git
    (иначе моноблок и ДЦ разъедутся).
  • Не подключаем рабочую 1С / VLAVKA без отдельного вашего «да».
  • Не включаем HTTPS/домен/push без отдельного «да».
  • Не публикуем порты 4100/5273 в открытый интернет без защиты.
  • FileZilla можно для просмотра файлов, но основной способ — Git + команды выше.
  • RDP для Linux-сервера Clover не нужен.


5. Если что-то сломалось после выката
-------------------------------------

  1) sudo systemctl stop clover-ui clover-api
  2) Вернуть снимок гипервизора (или git checkout предыдущего коммита)
  3) sudo systemctl start clover-api clover-ui
  4) Проверить health
  5) Написать @dsd: что меняли + что увидели


6. 1С и комп1 — отдельно от правок Clover
-----------------------------------------

  Правка кнопки/экрана в Clover  → только моноблок + выкат ДЦ.
  Смена URL/ключа обмена в 1С   → на компе1 (расширение), редко.
  Комп1 выключен                → сайт Clover жив, заказы в 1С не уходят,
                                  пока комп1 снова не включится.
