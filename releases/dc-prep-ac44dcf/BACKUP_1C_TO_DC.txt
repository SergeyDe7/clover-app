================================================================================
БЭКАПЫ 1С С КОМПА1 → ХРАНИЛИЩЕ В ДЦ
Понятная схема (база 1С остаётся на компе1)
Дата: 2026-08-02
================================================================================

Главное
-------
• Живая база 1С НЕ переезжает в ДЦ.
• Бэкап СНАЧАЛА делается на компе1.
• Потом КОПИЯ файла бэкапа уезжает в ДЦ (второй сейф).
• Это отдельно от бэкапа VM Clover (снимки гипервизора).


Схема
-----

  [Комп1, 24/7]
    1) 1С делает выгрузку/бэкап в папку, например:
       D:\Backup\1C\YYYY-MM-DD\
    2) По расписанию копия уезжает в ДЦ

  [ДЦ]
    Папка/диск только для копий, например:
      /backup/1c-from-office/
    или отдельный диск гипервизора «backup-1c»
    Сюда НЕ ставим рабочую 1С — только файлы копий.


Что нужно заранее
-----------------
【АНДРЕЙ / ДЦ】
  • Канал офис ↔ ДЦ (VPN или иной), чтобы комп1 видел шару/SFTP в ДЦ
  • Место под копии: размер = несколько полных бэкапов 1С
  • Способ приёма (выбрать один):
      A) SFTP/SSH на Linux (логин только для бэкапа, папка /backup/1c)
      B) Сетевая папка SMB в ДЦ, смонтированная на компе1 как диск
      C) Облако ДЦ / объектное хранилище (если площадка даёт)

【НА КОМПЕ1 — кто знает 1С】
  • Как сейчас делают бэкап: выгрузка .dt / штатное резервное копирование /
    SQL-бэкап (если клиент-сервер)
  • Папка локальных бэкапов
  • Расписание (например, ежедневно в 02:00)


Рекомендуемый простой вариант (часто так делают)
------------------------------------------------

Шаг 1. На компе1 — локальный бэкап 1С
  • Встроенное «Резервное копирование» / выгрузка в .dt
    по расписанию Планировщика Windows (или средствами 1С).
  • Файлы складывать в D:\Backup\1C\ (пример).
  • Хранить локально последние N дней (например, 7–14).

Шаг 2. В ДЦ — папка приёма
  Андрей создаёт, например:
    /backup/1c-from-office/
    пользователь backup1c (только эта папка, без sudo)
  Или SMB-шару \\dc-backup\1c

Шаг 3. Копирование по расписанию с компа1
  Вариант A — SFTP (если Linux в ДЦ):
    Программа WinSCP / rclone по расписанию:
    «после бэкапа 1С залить новые файлы из D:\Backup\1C\ на сервер».

  Вариант B — сетевой диск:
    Подключить шару ДЦ как Z:
    Планировщик: robocopy D:\Backup\1C Z:\1c /MIR /R:2 /W:5
    (или без /MIR — только копировать новые, чтобы не стереть лишнее)

Шаг 4. Проверка раз в неделю
  • На компе1 есть свежий файл бэкапа
  • В ДЦ тот же файл появился
  • Раз в месяц — пробное восстановление на ТЕСТОВУЮ базу
    (не на рабочую «на удачу»)


Чего не делать
--------------
  • Не считать снимок VM Clover бэкапом базы 1С — это разные вещи.
  • Не класть единственную копию только в ДЦ и удалять с компа1 сразу.
  • Не открывать папку бэкапов 1С в интернет без VPN/ACL.
  • Не восстанавливать бэкап поверх рабочей базы без отдельного плана.


Кто что делает
--------------
  Андрей / ДЦ: место, доступ, VPN/SFTP/SMB, квоты диска.
  Специалист 1С / вы на компе1: расписание выгрузки базы.
  Заказчик: решить «как часто» и «сколько копий хранить».
  @dsd: не настраивает 1С-бэкап на компе1 удалённо без доступа;
        может дать скрипт-шаблон копирования, когда будут IP и способ.


Мини-анкета, чтобы настроить конкретно
--------------------------------------
【】 База 1С: файловая / клиент-сервер (SQL)
【】 Сейчас бэкап уже есть? куда сохраняется?
【】 Желаемое расписание: ежедневно / … время: ____
【】 Сколько копий хранить в ДЦ: ____ дней
【】 Приём в ДЦ: SFTP / SMB / другое
【】 VPN офис↔ДЦ уже есть: да / нет


Связь с Clover
--------------
Бэкап 1С ≠ бэкап Clover.
Clover в ДЦ: снимки гипервизора (+ при желании копия server/data).
1С на компе1: схема из этого файла.
