Что такое «выкат»
-----------------
Это не установка с нуля. Clover на сервере УЖЕ стоит.
Выкат = взять новую версию кода с GitHub и включить её на VM в ДЦ.

Аналогия: обновить приложение на телефоне — старое работает, ставите новое,
проверяете, что открывается.


Картина целиком
---------------

  [Моноблок]                    [GitHub]                      [ДЦ]
  вы + Cursor/@dsd   →«коммит»→  main обновлён   →«выкат»→   сайт для людей
  правка проверена               хранилище кода               IP:5273 / потом домен


Кто нажимает кнопки на выкате
-----------------------------
Вариант А (удобнее на старте): пишете Андрею «выкати коммит … / main».
Вариант Б: вы сами по SSH (чёрное окно с командами) — шпаргалка ниже.
Вариант В: FileZilla только смотреть файлы; выкат всё равно командами.


================================================================================
СЦЕНАРИЙ А — Андрей выкатывает (как будет выглядеть для вас)
================================================================================

1. На моноблоке закончили правку, сделали «коммит», PR влит в main
   (или вы сказали Андрею точный номер коммита).

2. Вы пишете Андрею коротко, например:
   «Выкати на ДЦ main (или коммит abc1234). После — пришли health.»

3. Андрей на сервере:
   • при крупном обновлении — снимок VM;
   • скачивает код (git pull);
   • ставит зависимости и собирает интерфейс;
   • перезапускает две службы (API и UI);
   • проверяет health.

4. Андрей отвечает вам:
   • health: version 4.0.4 (или новая);
   • «открой http://<IP>:5273/».

5. Вы открываете сайт в браузере и проверяете то, что меняли
   (кнопка, заказ, уведомление и т.д.).

6. Если ок — готово. Если нет — откат (снимок) + пишете @dsd.


Время: обычно 5–15 минут, если сеть и GitHub доступны с VM.


================================================================================
СЦЕНАРИЙ Б — вы сами по SSH (как выглядит по минутам)
================================================================================

Подготовка один раз: Андрей даёт вам
  • IP сервера
  • логин (часто ваш пользователь + sudo, или clover)
  • способ входа: пароль или ключ
  • программу: Windows Terminal / PuTTY

--- Минута 0: снимок (по желанию, для крупного обновления) ---
  На панели гипервизора ДЦ: «снимок / snapshot» VM Clover.
  Или попросить Андрея сделать снимок.
  Перед снимком службы лучше остановить (команды stop ниже).

--- Минута 1: вход ---
  Открыли PuTTY / Terminal → подключились к IP → ввели пароль.
  Видите строку вроде:  user@clover-test:~$

--- Минута 2–3: обновить код ---
  Копируете команды по одной (Enter после каждой):

    cd /opt/clover/clover-app
    sudo -u clover git fetch origin
    sudo -u clover git checkout main
    sudo -u clover git pull

  Ожидание: текст «Already up to date» или список новых файлов.
  Проверка:
    sudo -u clover git rev-parse --short HEAD
  Должен совпасть с тем коммитом, что на GitHub после «коммита».

--- Минута 4–8: зависимости и сборка ---

    sudo -u clover npm ci
    cd server
    sudo -u clover npm ci
    cd ..
    sudo -u clover npm run build

  Ожидание: в конце build без красной ошибки, есть dist/.

--- Минута 9: перезапуск ---

    sudo systemctl restart clover-api clover-ui
    sudo systemctl status clover-api clover-ui --no-pager

  Ожидание: active (running) у обеих служб.

--- Минута 10: проверка на сервере ---

    curl -sS http://127.0.0.1:4100/api/health

  Ожидание: в ответе "ok":true и "version":"…"

--- Минута 11: проверка у себя ---
  В браузере на своём ПК:
    http://<ВНУТРЕННИЙ_IP_CLOVER>:5273/
  Логин → смотрите изменённое место.


Если на npm/git ошибка сети — не паникуем: службы старые ещё могут
работать, пока вы не сделали restart. Пишете Андрею / @dsd.


================================================================================
Что происходит «под капотом» (одним абзацем)
================================================================================

Git pull подменяет файлы программы на новые.
npm ci ставит библиотеки.
npm run build собирает сайт в папку dist.
systemctl restart гасит старый процесс Node и поднимает новый —
с этого момента люди видят обновлённый Clover.
База заказов (sqlite) и .env при обычном выкате НЕ стираются.


================================================================================
Что НЕ входит в обычный выкат
================================================================================

  • Переустановка Linux / Node «с нуля»
  • Перенос 1С / смена рабочих мест на компе1
  • Смена домена / HTTPS / VAPID (это этап 2, отдельное «да»)
  • Правка server/.env без необходимости
  • Merge в GitHub (это вы делаете «коммитом» / «да» на merge ДО выката)


================================================================================
Откат, если после выката плохо
================================================================================

Быстрый путь (если был снимок):
  1) Остановить Clover:  sudo systemctl stop clover-ui clover-api
  2) На гипервизоре — «восстановить снимок»
  3) Запустить:          sudo systemctl start clover-api clover-ui
  4) Проверить health и сайт

Через Git (если снимок не делали):
  sudo -u clover git checkout <СТАРЫЙ_КОММИТ>
  затем снова npm ci / build / restart
  (лучше с Андреем или @dsd)


================================================================================
Шпаргалка «скопировать Андрею»
================================================================================

Выкат Clover ДЦ:
  cd /opt/clover/clover-app
  sudo -u clover git fetch && sudo -u clover git checkout main && sudo -u clover git pull
  sudo -u clover npm ci && (cd server && sudo -u clover npm ci) && sudo -u clover npm run build
  sudo systemctl restart clover-api clover-ui
  curl -sS http://127.0.0.1:4100/api/health

Пришлите: вывод health + короткий HEAD (git rev-parse --short HEAD)
