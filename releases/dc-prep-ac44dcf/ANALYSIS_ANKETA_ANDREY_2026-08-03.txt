2. РИСКИ (по приоритету)
================================================================================

R1. Высокий — нет проверки комп1 → Clover:4100
    Факт: «ещё даже вм нет».
    Следствие: после установки Clover обмен не заработает, пока 1С
    с компа1 не откроет http://192.168.155.15:4100/api/health.
    Митигация: сразу после systemd — curl с компа1 / из сети 1С.

R2. Высокий — односторонний VPN / маршрутизация
    Андрей: «односторонний, замаршрутизирована подсеть ДЦ из офиса».
    Нужно: офис (комп1 + менеджеры 192.168.0.0/22) → ДЦ 192.168.155.15.
    Обратный маршрут ДЦ→комп1 для этапа 1 НЕ обязателен (pull).
    Риск: firewall ДЦ не пускает 4100/5273 с 192.168.0.0/22.
    Митигация: явные allow-правила на 4100 и 5273 с офисной подсети.

R3. Средний — RAM 2 GB
    npm ci / build на Debian могут упереться в OOM.
    Митигация: swap 2G или временно поднять RAM до 4 GB на время сборки.

R4. Средний — кто правит расширение 1С
    Андрей: «Сергей?» — не подтверждено.
    Без смены URL+ключа в 1С на компе1 ACK не будет.
    Митигация: явно назначить ответственного до приёмки.

R5. Средний — база «вроде TEST»
    Обмен только с X-Clover-Database: TEST. Если на компе1 откроют VLAVKA —
    отказ / риск путаницы.
    Митигация: заказчик подтверждает имя базы TEST до C10.

R6. Низкий — путаница 81.177.141.15
    Не использовать как APP_PUBLIC_URL на этапе 1.
    В .env: http://192.168.155.15:5273

R7. Низкий — FTP в ДЦ
    Не нужен для Clover (достаточно SSH/SFTP). Не путать с выкатом.

3. ОПТИМАЛЬНЫЙ ВАРИАНТ (решение)
================================================================================

Этап 1 (сейчас):
  1) Поднять VM Debian 13 @ 192.168.155.15 (как у Андрея).
  2) Поставить ТОЛЬКО Clover по INSTALL_FOR_ANDREY.txt (Linux + systemd).
  3) Обмен = только PULL из 1С (ONEC_BASE_URL — заглушка / не обязателен).
  4) Firewall: 4100+5273 только с 192.168.0.0/22 (+ сеть компа1, если отдельная).
  5) В 1С на компе1: URL http://192.168.155.15:4100 + X-Clover-Key + Database TEST.
  6) ONEC_WRITE_ENABLED=false до отдельного «да».
  7) Домен / HTTPS / 81.177.141.15 — НЕ трогать (этап 2).
  8) Бэкап 1С в ДЦ — не в этой установке.

Почему так:
  • Совпадает с ARCHITECTURE и с предложением Андрея (outbound только от 1С).
  • Не требует белого IP и двустороннего туннеля.
  • Минимальный scope: один сервис в ДЦ + правка URL/ключа в 1С TEST.
